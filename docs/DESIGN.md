# 公司专线（xdvpn-gateway）产品与架构设计

- 版本：r1.3（2026-10-24，按沙盒实现与演练结果修订；r1.3 改动见文末「修订记录」）
- 目标设备：RT-AX86U，koolcenter 388_24231 固件，软件中心 1.5 代（hnd），内核 4.1.52 aarch64，内存 1 GB
- 前身：`~/Code/Github/xdvpn-router`（2026-08-03 一天写成，只留作行为参考，不再迭代）
- 上游行为参考：kafeifei/XDVPN（macOS 客户端，openconnect 封装）

## 1. 一句话

路由器替全家拨通公司专线，全家上网都走公司线路（国内国际由公司侧分流）。**任何环节出问题，全家自动回到运营商直连，照常上网；恢复后自动切回。** 平时不需要人管，出问题时打开页面能一眼看懂发生了什么。

## 2. 目标与非目标

### 必须做到

1. 全家 IPv4 流量走公司隧道；指定设备（按 MAC）始终直连。
2. 公司线路、公司 DNS、插件本身，任何一层出问题都**回到直连而不是断网**，也不会卡住路由器。
3. 线路切换有防抖，不来回横跳；切换不重启 dnsmasq、不重载防火墙。
4. 重连有退避和每日上限，账号密码错误立即停手，不让公司账号被风控。
5. 常驻资源：守护程序内存 ≤ 6 MB，空闲 CPU ≈ 0；日志只在内存，不写闪存。
6. 页面白话：3 秒看懂"现在走哪条线、正常吗、刚才发生了什么"。
7. 软件中心离线包安装、升级、卸载干净，卸载后零残留。

### 明确不做（V2 前不加）

- 按域名分流、黑白名单、设备四态、实时访问观察页（旧版的复杂度来源）
- IPv6 走隧道（V1 对 LAN 转发的 IPv6 做丢弃，设备自动回退 IPv4，防泄漏）
- 和 Clash / 科学上网插件共存（两套同时接管全家流量就是现在不稳的根因；启用前停用它们）
- 多服务器配置、流量统计图表

### 可选开关（默认关闭）

- **国内网站直连**（详见 §3.6）：只让"中国服务"名单里的网站走运营商直连；其余（含 Apple、Sony 等全球服务）照常走公司海外线路。
- **异常通知**：长时间直连或密码失效时推送到手机（飞书群机器人 / Bark），直连持续 30 分钟才提醒。

## 3. 架构

```
           ┌──────────────── corpline（Rust 单文件守护，约 1.5 MB）────────────────┐
           │  状态机   健康探测   重连退避   DNS 转发(127.0.0.1:5354)   状态 JSON  │
           └──────┬──────────┬───────────────┬─────────────────────────┬──────────┘
                  │ 子进程    │ 每 15 s 探测   │ 原子切换                 │
           openconnect     公司 DNS        ipset corpline_live       /tmp/upload/corpline_status.json
           (Entware)       经隧道           (总阀门，唯一切换点)        ← 网页每 5 s 读取
                  │
              tun: corp0 ── table 88: default dev corp0
```

### 3.1 进程

- **corpline**：Rust 编译的静态程序（aarch64 musl，若实测为 32 位用户态则 armv7），无动态依赖。负责一切判断；网络改动只调用 `ip` / `iptables` 少量固定命令。
- **openconnect**：corpline 的子进程（前台模式，不用 `--background`，已实测它会重建 tun 丢配置）。密码经 stdin 传入，`--non-inter`、`--force-dpd=10`。corpline 解析其输出得知 DTLS 是否建立、认证是否失败。
- **看护**：cru 每分钟一次 `corpline ensure`，只检查守护进程是否在；不在则拉起。

### 3.2 路由：一个总阀门就是开关

- 启用时一次建立：mangle 链 `CORPLINE`——**只在新连接时判断**（直连设备、本机直连网段、组播、VPN 服务器、国内直连集合先 RETURN；其余若总阀门打开就给连接打 connmark `0x5000`），之后每个包按 connmark 恢复 fwmark；`ip rule fwmark 0x5000/0x5000 lookup 88 pref 8850` 常驻；nat `MASQUERADE -o corp0`，MSS clamp，rp_filter 放宽（all/br0/corp0，已实测是转发不通的根因）。
- **走公司线 / 回直连，只改 ipset `corpline_live` 的内容**（打开 = 0.0.0.0/1 + 128.0.0.0/1，关闭 = 清空）。原子、毫秒级、不碰防火墙规则。
- **切换不打断正在进行的连接**：连接在建立那一刻决定走哪条线并记在连接跟踪上。直连期间开始的下载、视频会议，切回公司线路后照常进行（沙盒实测 4 MB 慢速下载跨越切换完整收完）；切换只影响新连接。（r1.2 用增删 ip rule 做开关，会把已有连接整体搬到另一条线上而断开，r1.3 改掉。）
- **内核兜底**：table 88 的默认路由挂在 `corp0` 上。隧道消失 → 路由随网卡消失 → 规则查不到路由 → 内核自动落回 main 表直连。**即使 corpline 卡死，全家也不断网。**
- 不加 blackhole（不做"断线即断网"的 kill switch）。
- 发往 VPN 服务器自身的流量 RETURN，防环路；家里电脑自己开的公司 VPN 因此直连，不会"VPN 套 VPN"。直连网段每分钟按主路由表刷新一次（宽带换网段也跟得上）。
- 路由器自己经隧道发出的查询（DNS 转发、健康探测）套接字绑定 corp0，配一条 `ip rule oif corp0 lookup 88 pref 8849`。
- 安全：只加拒绝不加放行——从 corp0 进来的新连接一律丢弃（INPUT 与 FORWARD），不在华硕 FORWARD 链前插 ACCEPT，因此不会绕过家长控制等固件规则。IPv6：启用期间拒绝 LAN 转发的 IPv6（立即回 ICMPv6 拒绝），DNS 不回 AAAA，设备马上用 IPv4。

### 3.3 DNS：默认公司 DNS，个别例外改用海外 DNS；切换不重启 dnsmasq

**原则：公司 DNS 是主力。** 公司对海外与中国的解析和线路已经做过处理，且对 App Store 做过修正。2026-10-24 用 Mac 正常解析实测：`apps.apple.com` 经公司 DNS 得到美国节点，App Store 网页进入美国区；`itunes.apple.com` 虽解析到上海，但只 301 到 `apps.apple.com`；`www.apple.com` 解析到上海，页面为英文、不转跳。（r1.1 曾据"把请求强行指到上海节点"的测试判断 Apple 被切到中国区，方法有误，已撤回。）海外公共 DNS 只做备用与个别例外。

- dnsmasq 只改一次（`/jffs/configs/dnsmasq.d/corpline.conf`）：上游 = `127.0.0.1#5354`，运营商 DNS 保留在其后作兜底（`strict-order`）。**插件崩溃 → 5354 端口关闭 → dnsmasq 立即改问运营商 DNS。** 上线前在真机核对 servers-file 与 strict-order 的实际顺序。
- corpline 内置 DNS 转发（UDP 为主，TCP 兜底，无缓存，缓存交给 dnsmasq），按域名后缀匹配，优先级从高到低：

| 名单 | 内容 | 上游 |
|---|---|---|
| 1. 用海外解析的例外 | 默认只放 Apple 网页与商店：`apple.com`、`mzstatic.com`（系统更新下载 `swcdn.apple.com`、`updates.cdn-apple.com` 不放，国内节点更快、内容相同）；用户可增删 | 海外公共 DNS 经隧道（8.8.8.8 与 1.1.1.1 并行，先回先用） |
| 2. 中国服务（仅"国内网站直连"开启时） | felixonmars/dnsmasq-china-list accelerated-domains（约 11 万，已排除 Apple/Google） | 运营商 DNS，应答 IP 写入直连集合（§3.6） |
| 3. 其余全部（含公司内网） | — | **公司 DNS** |

- **实测依据（2026-10-24，公司 DNS，40 个常用海外服务）**：仅 Apple 的 `www.apple.com`、`itunes.apple.com`、`is1-ssl.mzstatic.com`、`swcdn.apple.com` 解析到中国节点；`apps.apple.com`（美国）、iCloud（香港）及微软、索尼、任天堂、Steam、亚马逊、Netflix、GitHub、ChatGPT、Claude 等均为海外节点。
- **退避链**：公司 DNS → 海外公共 DNS（经隧道）→ 运营商 DNS（仅隧道断开时）。任一上游 300 ms 无应答即并行问下一级，先回先用；连续 3 次超时标记不健康，每 30 s 一次探测查询，连续 3 次成功再恢复。
- **经隧道的查询绝不走直连**：发往公司 DNS 与海外 DNS 的套接字绑定隧道网卡（SO_BINDTODEVICE corp0），隧道不在就立即失败转入退避，不会从家里宽带发出而被污染或劫持。2026-10-24 实测经隧道：8.8.8.8、1.1.1.1 均 10/10 成功，首次查询 75–165 ms。
- **线路"临时直连"状态**：全部改问运营商 DNS；时间线写明，可选通知提醒。
- **不采用 fake-ip**：fake-ip 只在"按域名决定走哪条线、并由用户态代理转发每个连接"时才需要（Clash 的架构），代价是每个连接经过代理进程（CPU、内存、单点故障，即现在不稳的来源）、App 缓存假 IP 后重启失效、部分游戏/P2P 异常。本方案流量在内核整体走隧道，按域名的例外由"解析时写入 ipset"实现，路由效果等同 fake-ip，但没有代理进程。
- 名单为紧凑结构（排序后缀表，整块内存 + 偏移二分查找），仅开启国内直连时加载；首次开启时下载、之后每周一凌晨更新，条目数 ≥ 5 万才原子替换，失败保留旧表。
- **直连期间**：只问运营商 DNS，并把应答 TTL 压到 30 秒；**切回公司线路时给 dnsmasq 发 SIGHUP 清缓存**（不重启）。这样直连期间可能被污染的解析不会在切回后继续被用。进入直连时不清缓存：公司 DNS 给的国内地址直连也能用，海外地址直连本来就到不了。
- 旧版"覆盖 /tmp/resolv.dnsmasq"的做法废弃（WAN 重连会被固件重写，且崩溃时会让全屋 DNS 指向不可达地址）。

### 3.4 状态机

| 状态 | 页面文案 | 流量 | DNS | 进入条件 |
|---|---|---|---|---|
| `off` | 已关闭 | 直连 | 运营商 | 总开关关闭 |
| `connecting` | 正在连接公司线路 | 直连 | 运营商 | 启用 / 重连中 |
| `active` | 正在使用公司专线 | 隧道 | 公司 DNS（例外用海外） | 隧道建立且首轮探测通过 |
| `watching` | 公司线路有点慢，正在观察 | 隧道 | 公司 DNS（例外用海外） | 探测连续失败 1–2 次，或延迟 > 800 ms |
| `fallback` | 已临时切到直连 | 直连 | 运营商 | 探测连续失败 3 次（约 45 s），或隧道进程退出 |
| `autherr` | 公司账号登录失败 | 直连 | 运营商 | openconnect 报认证失败（终态，等用户改密码） |
| `paused` | 插件运行异常，已自动停用 | 直连 | 运营商 | 10 分钟内意外退出 ≥ 3 次（终态，等用户重新启用） |

- **回切防抖**：`fallback` 期间后台继续重连；隧道恢复后需连续健康 120 s 才切回 `active`。
- **退避**：重连间隔 5 s → 10 s → 30 s → 1 min → 2 min → 5 min，之后每 15 min；每日上限 60 次，到上限后保持直连到次日或用户手动重试。认证失败不计入、不重试。
- **健康探测**（每 15 s，单次开销 < 1 KB）：经隧道向公司 DNS 查一次公司域名；公司 DNS 不应答再经隧道问一次海外公共 DNS。**任一应答即线路正常**——只是公司 DNS 坏了不算线路坏了（DNS 层自己切备用，见 §3.3）。DTLS 退回 TLS 只在页面显示，不算失败（TLS 也能用，只是慢一点）。（r1.2 的"收包计数"判据去掉：黑洞时探测本身就会失败，沙盒验证足够。）
- **隧道在但一直不通**：已切直连后探测再连续失败 4 次（约 80 s）→ 主动重建连接（沙盒实测：SIGSTOP 冻住的 openconnect 也能被结束，SIGTERM 无效时 12 s 后 SIGKILL）。
- **openconnect 自身异常**：常驻内存超过 40 MB、CPU 连续 60 s 占满 → SIGTERM，12 s 后 SIGKILL，进入重连流程。openconnect 设 `--reconnect-timeout=60`：它自己 60 s 内重连不上就退出，交给 corpline 的退避。corpline 退出时内核给 openconnect 发 SIGTERM（PR_SET_PDEATHSIG），不留孤儿进程、隧道随之消失。
- **宽带恢复立即重连**：主路由表的默认路由重新出现时，不等退避，立即重连（沙盒：宽带断 40 s 恢复后 129 s 回到公司专线，其中 120 s 是稳定期）。
- 公司服务器地址由 corpline 经运营商 DNS 解析好，以 `--resolve` 交给 openconnect，不依赖家里的 DNS 链路。

### 3.5 开机与启用的安全顺序

1. 开机先保持直连；WAN 就绪（S96 钩子）后才启动 corpline。
2. 启用时先建隧道、先探测，**通过后才加切换规则**；失败就停在直连。
3. 防火墙重建（N96 钩子）只重建 iptables 链，不动隧道与路由规则。
4. 防"开机即坏"：每次开机计数 +1，守护程序稳定运行 10 分钟后清零；计数到 3 → 自动停用（不依赖开机时钟是否已同步）。
5. 管理这台路由器的电脑（Mac Studio）默认列入直连设备，界面上锁定说明原因（第一次启用时按网页登录 IP 查 ARP 得到 MAC）。
6. 崩溃即撤：守护程序外面套一层 sh 阻塞等待它退出（不占 CPU）。不是用户主动停的退出（崩溃、被系统杀掉）→ 立刻撤掉全部网络改动（含 dnsmasq 转发），再拉起。沙盒实测：崩溃后 1 秒内全家解析照常（16 ms），2 秒回到公司专线。（若不撤，dnsmasq 的 strict-order 会让每次解析先等一次超时，约 1–5 秒。）
7. 看护（cru 每分钟，兜底）：守护程序不在就拉起；10 分钟内拉起 ≥ 3 次 → 自动停用（撤掉全部网络改动，页面显示原因与"重新启用"）。

### 3.6 国内网站直连（可选开关，默认关闭）

- **只对"中国服务"名单生效，不按 IP 地理位置判断。** 按 IP 判断会把全球品牌的中国节点也算作国内，与"全球服务走海外"冲突，已放弃（r1 曾写 chnroutes2 方案，2026-10-24 Chris 否决：海外账号用户访问全球服务被切到中国节点会出问题）。
- 实现：转发器解析"中国服务"名单内的域名时，把应答 IP 写入 `ipset corpline_cn`（hash:ip，带超时 = 记录 TTL，下限 5 min）。mangle 链打标前 `-m set --match-set corpline_cn dst -j RETURN`，这些连接走运营商直连。内核匹配，无用户态转发。
- 名单 1（用海外解析的例外）优先于名单 2；中国服务名单本身已排除 Apple、Google。
- 关闭开关时：中国服务仍用公司 DNS 解析、经公司中国线路访问；ipset 规则不生效。

### 3.7 资源预算（上线验收项）

| 项 | 预算 |
|---|---|
| corpline 常驻内存 | ≤ 6 MB |
| corpline 空闲 CPU | 15 s 一次探测之外 ≈ 0 |
| openconnect 内存 | 约 5–10 MB（不可省，取决于 GnuTLS） |
| 日志 | 内存环形缓冲 256 KB；切换事件另存最近 200 条到 `/tmp`；**不写 jffs / 闪存** |
| 程序体积 | ≤ 2 MB（放 `/koolshare/bin`） |

## 4. 页面（详见 `prototype/index.html`）

- 嵌在华硕后台软件中心外框内，内容区 760 px，沿用后台深色底 `#4D595D` 与华硕蓝 `#248DFF` 主按钮，避免像外来页面。
- 结构：标题与总开关 → 状态卡（当前线路、已稳定时长、今日流量、延迟；异常时附原因和一个动作按钮）→ 最近发生了什么（白话时间线）→ 设置（公司账号、直连设备、国内网站直连、异常通知、高级）→ 页脚资源占用。
- 颜色只表达一种意思：绿色 = 公司专线正常；中性灰 = 进行中/观察中；橙色 = 已降级到直连；红色 = 需要你处理（账号失败、插件停用）。
- 后台为单一深色主题、中文界面，故不出浅色与多语言版本（与华硕后台一致）。

## 5. 工程与测试（不在家用路由器上做实验）

1. **单元测试**：状态机、退避、DNS 退避用模拟时钟和模拟故障测试，覆盖每一条状态转换。
2. **本机完整网络演练**（Mac Studio 上的 Linux 虚拟机 / 容器）：三个网络命名空间——"家里设备"、"路由器"（跑真实 corpline + openconnect + iptables）、"假公司 VPN"（ocserv）。用 `tc netem` 制造丢包/延迟，`kill -9`、`kill -STOP` 卡死进程，DNS 黑洞，认证失败，逐项验证会正确退避并回到直连。不用公司真实账号。
3. **真机上线**（用户指定时间）：先以"已安装、未启用"装上（零影响）→ 只给一台不重要的设备启用 → Mac Studio 始终直连 → 5 分钟内不确认自动恢复原状 → 稳定后扩到全家。
4. **验收门**：G1 本机演练全部故障场景通过；G2 真机单设备 24 小时无人干预；G3 全家启用一周，故障注入（拔 WAN、重启路由器）自动恢复；卸载零残留。

## 5.1 沙盒演练（G1）

`lab/`：Linux 虚拟机里用网络命名空间搭"家里设备 / 路由器 / 运营商 / 公司"，ocserv 扮公司 VPN（自签 CA，openconnect 照样走 CA 校验），dnsmasq 扮运营商 DNS（对 google 返回污染地址）、公司 DNS、海外 DNS；路由器侧用 iptables-legacy、华硕风格防火墙、模拟的软件中心（dbus / cru / service / base.sh），用真实的 install.sh、外壳脚本、守护程序、openconnect、dnsmasq。`sudo bash lab/run.sh` 逐项故障演练，结果写入 `lab/report/RESULTS.md`。

2026-10-24 第 5 轮全量：19 个场景 93 项检查全部通过（明细见 Designs 下 `沙盒演练结果.md`）。资源：守护程序常驻 712 KB（载入 11 万条国内名单 2.5 MB），空闲 CPU 约 0.03%，1000 次不同域名查询（20 并发）93 ms；openconnect 约 19 MB。

## 修订记录

- **r1.3（2026-10-24，沙盒实现后）**
  - 切换开关从"增删 ip rule"改为"ipset 总阀门 + connmark"：切换不再打断已有连接（§3.2）。
  - 健康探测：公司 DNS 不应答时再问海外 DNS，公司 DNS 故障不再误判为线路故障；DTLS 降级不算失败；去掉收包计数判据（§3.4）。
  - 新增：直连后隧道仍不通约 80 s 主动重建；宽带恢复立即重连；openconnect `--reconnect-timeout=60`、`--resolve`、PR_SET_PDEATHSIG（§3.4）。
  - DNS：直连期间 TTL 压到 30 s，切回时 SIGHUP 清 dnsmasq 缓存；不回 AAAA，拒绝 LAN 的 IPv6 转发（§3.2、§3.3）。
  - 防火墙只加拒绝不加放行，不绕过固件的家长控制等规则（§3.2）。
  - 开机即坏保护改为"开机计数 + 稳定 10 分钟清零"，不依赖开机时钟（§3.5）。
  - 新增"崩溃即撤"：守护程序意外退出时立即撤掉网络改动并拉起，不等每分钟看护（§3.5）。
  - 异常通知：直连持续 30 分钟才提醒（短暂波动不打扰），与页面文案一致。
  - 修复：openconnect 被强杀后残留的隧道信息文件会让下一次连接的 45 秒超时失效；现在退出时与每次连接前都清掉。
  - 修复：断电后 /jffs 上残留的 dnsmasq 转发配置，开机先撤掉。
